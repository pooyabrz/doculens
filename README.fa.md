# شروع کار با DocuLens

این بسته، **نسخه آغازین ۰٫۱** پروژه دستیار پرسش‌وپاسخ از اسناد است. مسیر اولیه با Python و Streamlit ساخته شده تا بدون تجربه زیاد در توسعه وب بتوانی منطق پروژه را اجرا و بررسی کنی.

حالت پیش‌فرض، بخش‌های مرتبط متن را با جست‌وجوی واژه‌ای BM25 نمایش می‌دهد و هیچ مدل یا API پولی را فراخوانی نمی‌کند. اتصال اختیاری Ollama برای تولید پاسخ هم آماده است؛ کیفیت آن باید با مدل انتخابی بررسی شود.

## مرحله ۱: اجرای پروژه

۱. Python 3.12 را نصب کن یا نسخه فعلی را بررسی کن. این بسته روی Python 3.12 آزموده شده است.

۲. فایل ZIP را استخراج کن و یک ترمینال در پوشه `doculens` باز کن.

۳. دستورهای سیستم‌عامل خودت را اجرا کن. نیازی به فعال کردن محیط مجازی نیست؛ دستورها مستقیماً از Python همان محیط استفاده می‌کنند.

ویندوز، در PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

لینوکس یا macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

نصب بسته‌ها به اینترنت نیاز دارد. بعد از نصب، حالت نمایش شواهد به کلید API یا مدل نیاز ندارد.

۴. صفحه برنامه معمولاً خودکار باز می‌شود. در غیر این صورت، این نشانی را باز کن: http://localhost:8501

۵. روی «بارگذاری اسناد نمونه» کلیک کن و روش پاسخ را روی «نمایش شواهد — بدون مدل» نگه دار.

۶. این سؤال را وارد کن:

```text
مرخصی سالانه چند روز است؟
```

در بخش مرتبط باید عبارت «۲۴ روز مرخصی» را ببینی. روی منبع کلیک کن و متن اصلی را بررسی کن. در این حالت، متن سند نمایش داده می‌شود و پاسخ مولد تولید نمی‌شود.

۷. سؤال `ماهواره مدار زمین` را امتحان کن. در نمونه فعلی، نتیجه واژه‌ای پیدا نمی‌شود.

۸. یک سند را از فهرست دامنه جست‌وجو خارج کن و بررسی کن که منابع پاسخ فقط از اسناد انتخاب‌شده باشند.

برای توقف برنامه، در ترمینال `Ctrl+C` بزن.

## مرحله ۲: شناخت کد

این فایل‌ها را به ترتیب بخوان:

1. `doculens/models.py`: ساختار سند، بخش متن، نتیجه جست‌وجو و پاسخ.
2. `doculens/documents.py`: خواندن فایل، تقسیم متن و نگهداری محل منبع.
3. `doculens/retrieval.py`: نرمال‌سازی متن و رتبه‌بندی واژه‌ای BM25.
4. `app.py`: رابط کاربری و نگهداری اسناد در هر نشست.
5. `doculens/generation.py`: اتصال اختیاری مدل و بررسی ارجاع‌ها.

در PDF، شماره صفحه به ترتیب واقعی صفحات فایل اشاره می‌کند؛ ممکن است با شماره چاپ‌شده روی صفحه متفاوت باشد. TXT و Markdown شماره بخش دارند و شماره صفحه ساختگی دریافت نمی‌کنند.

## مرحله ۳: اجرای آزمون‌ها

ویندوز:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m evals.run_retrieval
```

لینوکس یا macOS:

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m evals.run_retrieval
```

آزمون‌ها تماس واقعی با مدل ندارند. مجموعه ۱۰ سؤال، بررسی اولیه مسیر بازیابی است و نتیجه آن را نباید دقت عمومی سیستم هوش مصنوعی معرفی کرد.

## مرحله ۴: آماده کردن داده واقعی

سه PDF متنی عمومی یا دارای مجوز استفاده انتخاب کن. برای هر سؤال، پاسخ مورد انتظار و صفحه شاهد را ثبت کن. در مجموع:

- هفت سؤال دارای پاسخ روشن در اسناد؛
- سه سؤال که پاسخ آن‌ها در اسناد نیست؛
- چند عبارت متفاوت برای یک مفهوم، برای مشخص شدن محدودیت جست‌وجوی واژه‌ای.

اگر می‌خواهی فارسی‌ـ‌انگلیسی را بررسی کنیم، سؤال فارسی درباره سند انگلیسی هم اضافه کن. نسخه فعلی بازیابی معنایی ندارد و موفقیت در این حالت تضمین نمی‌شود.

## مرحله ۵: انتخاب مدل و ادامه ساخت

پس از اجرای موفق نسخه نمونه، با توجه به بودجه یا مقدار RAM و GPU، مدل را انتخاب می‌کنیم. سپس embedding و جست‌وجوی معنایی را اضافه و با BM25 مقایسه می‌کنیم.

اگر از قبل Ollama و یک مدل نصب‌شده داری، روش «پاسخ با Ollama» را انتخاب کن و نام دقیق مدل را از خروجی `ollama list` وارد کن. هیچ مدل پیش‌فرضی دانلود نمی‌شود.

مدل باید خروجی ساختاریافته مورد نیاز را پشتیبانی کند. منبع ناشناخته و نقل‌قولی که در متن نباشد رد می‌شوند، اما وجود نقل‌قول به‌تنهایی درست بودن ادعا را اثبات نمی‌کند. پاسخ‌ها باید با مجموعه ارزیابی بررسی شوند. مدل‌های ابری Ollama ممکن است محتوای پرسش و شواهد را به ارائه‌دهنده ارسال کنند؛ برای اجرای محلی، مدل دانلودشده و تنظیمات مناسب Ollama لازم است.

## مرحله ۶: قرار دادن نسخه آغازین در گیت‌هاب

یک مخزن جدید و خالی با نام دلخواه، مثلاً `doculens`، ایجاد کن. اگر از فرمان‌های زیر استفاده می‌کنی، هنگام ایجاد مخزن در سایت GitHub، README و LICENSE دیگری اضافه نکن.

در پوشه پروژه:

```bash
git init
git add .
git commit -m "Add DocuLens v0.1 evidence-first prototype"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/doculens.git
git push -u origin main
```

`YOUR_USERNAME` و نام مخزن را با اطلاعات خودت جایگزین کن. ورود به GitHub باید با روش معمول Git خودت انجام شود. فایل‌های شخصی، کلیدها و اسناد محرمانه را وارد مخزن نکن.

بعد از push، GitHub Actions آزمون‌های تنظیم‌شده را اجرا می‌کند. این بسته روی حساب گیت‌هاب تو منتشر نشده است.

## محدودیت‌های این مرحله

پردازش هم‌زمان و ذخیره‌سازی در حافظه نشست است. OCR، پایگاه داده دائمی، جست‌وجوی معنایی، پاسخ‌های وابسته به تاریخچه، ورود کاربران و استقرار عمومی هنوز ساخته نشده‌اند. فایل‌ها روی دیسک ذخیره نمی‌شوند و با از دست رفتن نشست ممکن است از دسترس خارج شوند. حذف سند، تاریخچه پاسخ‌ها را نیز پاک می‌کند تا متن آن در گفت‌وگوی فعلی باقی نماند.

مسیر ادامه در [نقشه راه](docs/roadmap.md) و نتایج بررسی در [گزارش آزمون](docs/validation.md) آمده است.
